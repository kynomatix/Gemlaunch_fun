## 🔴 **NEW CRITICAL ISSUE**

### **C-3: Incomplete _update() Function - Missing Exemptions**

**Severity:** CRITICAL (Blocks Core Functionality)  
**Location:** BondingCurvePool.sol `_update()` override

**Issue:**
The V2 spec shows a simplified `_update()` function that's **missing several critical exemptions** from the original implementation.

**Current V2 Code (INCOMPLETE):**
```solidity
function _update(address from, address to, uint256 amount) internal override {
    if (to != address(0) &&
        to != address(this) &&
        to != graduationOracle &&
        !isVestingContract[to] &&  // ✅ NEW: Vesting exemption
        !graduated) {
        
        uint256 maxWallet = totalSupply() * MAX_WALLET_PCT / 100;
        require(balanceOf(to) + amount <= maxWallet, "Exceeds max wallet");
    }
    super._update(from, to, amount);
}
```

**What's Missing:**
1. ❌ `to != airdropTreasury` - Airdrop treasury needs to hold >10%
2. ❌ `to != owner()` - Owner needs exemption for emergency operations
3. ❌ `from != airdropTreasury` - Allow distributions from airdrop treasury
4. ❌ `from != address(this)` - Allow bonding curve buy operations

**Impact:**
- Bonding curve buys will fail (can't transfer from contract to users if they'd exceed 10%)
- Airdrop treasury can't hold vested allocations
- Emergency operations blocked

**Required Fix:**
```solidity
function _update(address from, address to, uint256 amount) internal virtual override {
    // Exemptions for wallet cap:
    // 1. Contract itself (holds curve + LP supply)
    // 2. Airdrop treasury (holds vested allocations)
    // 3. Graduation oracle (receives LP tokens)
    // 4. Owner (emergency operations)
    // 5. Vesting contracts (can hold up to 25%)
    // 6. Transfers FROM airdropTreasury (distributions)
    // 7. Transfers FROM contract (buy operations)
    // 8. Graduated tokens (no restrictions)
    
    if (to != address(0) &&
        to != address(this) && 
        to != airdropTreasury &&           // ✅ ADD THIS
        to != graduationOracle &&
        to != owner() &&                    // ✅ ADD THIS
        from != airdropTreasury &&          // ✅ ADD THIS
        from != address(this) &&            // ✅ ADD THIS
        !isVestingContract[to] &&
        !graduated) {
        
        uint256 maxWallet = totalSupply() * MAX_WALLET_PCT / 100;
        require(balanceOf(to) + amount <= maxWallet, "Exceeds max wallet");
    }
    
    super._update(from, to, amount);
}
```

## 🟠 **MEDIUM SEVERITY ISSUE**

### **M-3: Overly Restrictive Beneficiary Validation**

**Severity:** MEDIUM  
**Location:** TokenFactory.sol validation

**Issue:**
The code requires **all three beneficiary addresses** even if their allocation is 0%.

**Current Code:**
```solidity
if (reservedPercentage > 0) {
    // ... allocation checks
    
    // ❌ Always requires all beneficiaries, even if allocation is 0
    require(airdropBeneficiary != address(0), "Invalid airdrop beneficiary");
    require(marketingBeneficiary != address(0), "Invalid marketing beneficiary");
    require(teamBeneficiary != address(0), "Invalid team beneficiary");
```

**Scenario:**
```
reservedPercentage = 20%
airdropsAllocation = 0%    ← No airdrop vesting
marketingAllocation = 100%
teamAllocation = 0%        ← No team vesting

Current code STILL requires:
- airdropBeneficiary != address(0)  ← Unnecessary!
- teamBeneficiary != address(0)     ← Unnecessary!
```

**Impact:**
- Forces users to provide dummy addresses for unused vesting types
- Confusing UX (why provide an address if it won't be used?)
- Unnecessary gas cost for validation

**Required Fix:**
```solidity
if (reservedPercentage > 0) {
    uint256 totalAllocations = airdropsAllocation + marketingAllocation + teamAllocation;
    require(totalAllocations == 100, "Allocations must sum to exactly 100%");
    
    // ✅ Only validate beneficiaries if their allocation > 0
    if (airdropsAllocation > 0) {
        require(airdropBeneficiary != address(0), "Invalid airdrop beneficiary");
    }
    if (marketingAllocation > 0) {
        require(marketingBeneficiary != address(0), "Invalid marketing beneficiary");
    }
    if (teamAllocation > 0) {
        require(teamBeneficiary != address(0), "Invalid team beneficiary");
    }
    
    // ✅ Duplicate checks only for active allocations
    if (airdropsAllocation > 0 && marketingAllocation > 0) {
        require(airdropBeneficiary != marketingBeneficiary, "Duplicate beneficiaries");
    }
    if (airdropsAllocation > 0 && teamAllocation > 0) {
        require(airdropBeneficiary != teamBeneficiary, "Duplicate beneficiaries");
    }
    if (marketingAllocation > 0 && teamAllocation > 0) {
        require(marketingBeneficiary != teamBeneficiary, "Duplicate beneficiaries");
    }
}
```
