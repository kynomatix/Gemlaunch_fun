## 🧩 Architecture Validation

The architecture correctly modularizes into:

* **TokenFactory.sol** → Token + Pool deployment
* **BondingCurvePool.sol** → Trade logic, fee routing, anti-whale mechanics
* **GraduationController.sol** → DEX migration logic
* **Treasury/VestingVault.sol** → Fee distribution, buybacks, and DAO transition

The design cleanly separates **economic logic** from **governance**, but the **cross-contract atomicity** between the BondingCurvePool and GraduationController is not yet hardened.

## ⚙️ Detailed Contract Analysis

### 1. BondingCurvePool.sol

#### **Critical – Inconsistent Pricing Logic**

The midpoint formula:

```solidity
tokensPerETH = (remainingTokens - (tokenAmount / 2)) * 1e18 / 
               (address(this).balance + (ethAmount / 2));
```

* Fails to conserve value over round-trip buy-sell cycles.
* Susceptible to division-by-zero and rounding spikes at low liquidity.
* Encourages arbitrage manipulation if a trader repeatedly buys/sells around threshold points.

**✅ Recommendation:**
Implement a deterministic **virtual reserve model** (Uniswap v2-like invariant):

```solidity
k = x * y
price = Δx / (y - Δy)
```

Use `getAmountOut` / `getAmountIn` utilities from UniswapV2Math for MEV resilience.

---

#### **High – Fee Accounting Drift**

`totalRaised` is incremented and decremented incorrectly:

```solidity
totalRaised += tradeAmount; // buy
totalRaised -= kasRefund;   // sell (pre-fee)
```

This desynchronizes accounting and can block graduation if totalRaised < threshold after heavy trading.

**✅ Fix:**
Track two variables:

```solidity
uint256 public grossRaised; // all deposits
uint256 public netReserves; // current liquidity
```

Use `netReserves` for pricing and graduation.

---

#### **High – Unsafe Native Sends**

All `.transfer()` calls can fail under gas-intensive treasury wallets.
**✅ Fix:** Replace with:

```solidity
(bool ok, ) = treasury.call{value: amount}("");
require(ok, "Treasury send failed");
```

Apply CEI ordering and nonReentrant guard.

---

#### **High – Slippage and Deadline**

Currently, users have no protection against front-running or price jumps.

**✅ Add:**

```solidity
function buyTokens(uint256 minOut, uint256 deadline) external payable;
function sellTokens(uint256 tokenAmount, uint256 minOut, uint256 deadline) external;
```

---

#### **Medium – Wallet Cap Misapplied**

Cap uses total supply instead of circulating supply:

```solidity
require(balance + tokens <= totalSupply() * MAX_WALLET_PCT / 100)
```

**✅ Fix:**

```solidity
uint256 circulating = totalSupply() - balanceOf(address(this));
```

---

#### **Medium – Creator Fee Push at Graduation**

If the creator address is a contract with a revert-on-receive, graduation can brick.

**✅ Fix:** Switch to pull pattern:

```solidity
function withdrawCreatorFees() external {
    require(msg.sender == creator);
    uint256 amount = creatorFeesAccumulated;
    creatorFeesAccumulated = 0;
    _safeSend(msg.sender, amount);
}
```

### 2. GraduationController.sol

#### **Critical – Non-Atomic Graduation**

Flow:

1. Check threshold
2. Pay creator
3. Transfer liquidity
4. Add to DEX
5. Lock curve

If a buy occurs between steps 1–3, graduation executes with outdated reserves → exploitable arbitrage.

**✅ Fix:**

* Add `graduating` state flag.
* First set `graduating = true` and lock all trades.
* Snapshot reserves and complete LP add atomically.
* Mark `graduated = true` and emit event.

---

#### **High – Router Assumption Risk**

You assume:

```solidity
addLiquidityETH(address token, uint amountTokenDesired, ...)
```

Kaspa Finance router may differ (Kaspa uses WKAS wrapped asset).
**✅ Fix:** Confirm ABI or wrap with adapter contract.

---

### 3. Treasury/VestingVault.sol

#### **High – TWAP Buyback Risk**

Current implementation executes:

```solidity
router.swapExactETHForTokens(...)
IERC20(gemToken).transfer(address(0xdead), balance);
```

* No price validation → potential to buy at inflated prices.
* Predictable timing → sandwichable.

**✅ Fix:**

* Integrate on-chain TWAP oracle from Kaspa Finance DEX.
* Use randomized keeper delay.
* Introduce buyback spread to smooth volatility.

---

#### **Medium – Unbounded Fee Distribution**

Entire balance is distributed per call, risking gas bloat or uneven timing.
**✅ Fix:** Implement minimum threshold and partial payouts:

```solidity
if (balance > MIN_THRESHOLD) distributeProportionally();
```

---

### 4. TokenFactory.sol

#### **High – Anti-Spam Incomplete**

Without a deployment fee or rate limiter, token spam is trivial.
**✅ Fix:**

```solidity
require(msg.value >= CREATE_FEE);
require(block.timestamp - lastCreate[msg.sender] > 10 minutes);
```
