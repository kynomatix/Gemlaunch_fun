## 🔴 **CRITICAL ISSUES**

### **C-1: Constructor Only Mints Partial Supply**

**Severity:** CRITICAL (Blocks Deployment)  
**Location:** BondingCurvePool.sol constructor

**Issue:**
The constructor only mints `curveSupply + vestingSupply`, missing the 25% LP tokens!

**Current Code:**
```solidity
uint256 curveSupply = totalSupply * (75 - _reservedPercentage) / 100;
uint256 vestingSupply = totalSupply * _reservedPercentage / 100;

// ❌ Only mints curve + vesting
_mint(address(this), curveSupply);
if (vestingSupply > 0) {
    _mint(address(this), vestingSupply);
}
```

**Example (10% vesting):**
- Curve: 65% ✓
- Vesting: 10% ✓
- LP: 25% ❌ **MISSING!**
- Total minted: 75% (should be 100%)

**Impact:**
- LP tokens don't exist
- Graduation will fail (can't transfer non-existent tokens)
- Total supply is wrong

**Required Fix:**
```solidity
constructor(
    // ... params
    uint8 _reservedPercentage
) {
    // ... validation
    
    // ✅ Calculate allocations (for tracking only)
    uint256 curveSupply = totalSupply * (75 - _reservedPercentage) / 100;
    uint256 vestingSupply = totalSupply * _reservedPercentage / 100;
    uint256 lpSupply = totalSupply * 25 / 100;  // Always 25%
    
    // ✅ Mint ENTIRE supply to contract
    _mint(address(this), totalSupply);
    
    // ✅ Initialize virtual reserves (only curve supply is tradeable)
    virtualTokenReserve = curveSupply;
    virtualKasReserve = INITIAL_VIRTUAL_KAS;
    
    // Note: LP (25%) + Vesting stay in contract
    // Vesting will be transferred by factory
    // LP will be used during graduation
}
```

**Verification:**
```solidity
// At deployment:
totalSupply() == 1,000,000,000 tokens
balanceOf(address(this)) == 1,000,000,000 tokens ✓
virtualTokenReserve == curveSupply (e.g., 650M for 10% vesting)
Remaining in contract == lpSupply + vestingSupply (e.g., 250M + 100M = 350M)
```

### **C-2: Unallocated Vesting Tokens Stuck Forever**

**Severity:** CRITICAL (Financial Loss)  
**Location:** TokenFactory.sol allocation validation

**Issue:**
Allocations can sum to < 100%, leaving tokens stuck in the contract with no way to retrieve them.

**Current Code:**
```solidity
require(
    airdropsAllocation + marketingAllocation + teamAllocation <= 100,
    "Allocations cannot exceed 100%"
);
```

**Attack Scenario:**
```
reservedPercentage = 20% (200M tokens)
airdropsAllocation = 40% → 80M tokens
marketingAllocation = 30% → 60M tokens
teamAllocation = 20% → 40M tokens
Total allocated = 90% → 180M tokens

Remaining 10% (20M tokens) = STUCK FOREVER
```

**Why Stuck:**
1. `distributeReserve()` is blocked: `require(reservedPercentage == 0, "PRO tokens use vesting contracts")`
2. No other function can claim these tokens
3. Not in vesting contracts
4. Not in curve (virtualTokenReserve)
5. Not in LP allocation

**Impact:**
- Creator loses access to 20M tokens (in example)
- Tokens remain in contract forever
- Economic inefficiency

**Required Fix (Option 1 - Strict):**
```solidity
require(
    airdropsAllocation + marketingAllocation + teamAllocation == 100,
    "Allocations must sum to exactly 100%"
);
```

**Required Fix (Option 2 - Flexible with Remainder Handler):**
```solidity
// Allow <= 100 but handle remainder
uint256 totalAllocated = airdropsAllocation + marketingAllocation + teamAllocation;
require(totalAllocated <= 100, "Allocations exceed 100%");

// Calculate remainder
uint256 totalVesting = totalSupply * reservedPercentage / 100;
uint256 airdropTokens = totalVesting * airdropsAllocation / 100;
uint256 marketingTokens = totalVesting * marketingAllocation / 100;
uint256 teamTokens = totalVesting * teamAllocation / 100;

uint256 remainderTokens = totalVesting - airdropTokens - marketingTokens - teamTokens;

// ✅ If remainder exists, add to creator's choice (e.g., team vesting)
if (remainderTokens > 0) {
    teamTokens += remainderTokens;
}
```

**Recommendation:**
Use **Option 1 (Strict)** for simplicity and clarity. Require allocations to sum to exactly 100%.

### **H-2: No Validation for Duplicate Beneficiaries**

**Severity:** HIGH  
**Location:** TokenFactory.sol beneficiary validation

**Issue:**
Nothing prevents the same address from being used for multiple vesting types, which could cause:
1. Confusion in UI (same wallet sees multiple vesting entries)
2. Economic centralization (one wallet controls all vesting)

**Example:**
```solidity
airdropBeneficiary = 0xCreator
marketingBeneficiary = 0xCreator
teamBeneficiary = 0xCreator

// All vesting goes to same wallet - defeats purpose of separation
```

**Impact:**
- Defeats the purpose of separate vesting schedules
- UI confusion (which vesting contract to claim from?)
- Potential for mistakes in claiming

**Recommendation:**
```solidity
require(airdropBeneficiary != marketingBeneficiary, "Duplicate beneficiaries");
require(airdropBeneficiary != teamBeneficiary, "Duplicate beneficiaries");
require(marketingBeneficiary != teamBeneficiary, "Duplicate beneficiaries");
```

**Note:** This could be downgraded to a warning if there's a legitimate use case for same beneficiary.

function createToken(
    // ... params
    uint8 reservedPercentage,
    uint8 airdropsAllocation,
    uint8 marketingAllocation,
    uint8 teamAllocation,
    address airdropBeneficiary,
    address marketingBeneficiary,
    address teamBeneficiary

    // Validate vesting params

    if (reservedPercentage > 0) {

            "Allocations must sum to exactly 100%"

        require(
            airdropsAllocation > 0 || marketingAllocation > 0 || teamAllocation > 0,

        require(airdropBeneficiary != teamBeneficiary, "Duplicate beneficiaries");
        require(marketingBeneficiary != teamBeneficiary, "Duplicate beneficiaries");

    // Deploy pool
    BondingCurvePool pool = new BondingCurvePool(
        name,
        symbol,
        totalSupply,
        msg.sender,
        treasury,
        airdropTreasury,
        platformDevelopmentWallet,
        antiBotEnabled,

        admin,

    if (reservedPercentage > 0) {

        if (airdropTokens > 0) {

                poolAddress,

            airdropVestingAddress = address(av);
            pool.transferReserveToVesting(airdropVestingAddress, airdropTokens);
            
            require(
                IERC20(poolAddress).balanceOf(airdropVestingAddress) == airdropTokens,
                "Airdrop vesting underfunded"
            );

        // ... same for marketing and team

        pool.finalizeVestingSetup();

    tokens[poolAddress] = TokenInfo({...});
    deployedTokens.push(poolAddress);
    
    emit TokenCreated(...);
    emit VestingDeployed(poolAddress, airdropVestingAddress, marketingVestingAddress, teamVestingAddress);
    
    return (poolAddress, airdropVestingAddress, marketingVestingAddress, teamVestingAddress);
}
