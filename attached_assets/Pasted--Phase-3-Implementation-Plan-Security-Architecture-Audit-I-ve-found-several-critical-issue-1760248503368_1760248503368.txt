## 🔴 **CRITICAL ISSUES**

### C-1: Transaction Flow Architecture is Flawed
**Location**: Section 3.0, Phase 4 "Relay"  
**Issue**: The plan shows a "relay" step where backend submits transactions after wallet signing. This is **architecturally wrong** for MetaMask.

**Current (Wrong) Flow**:
```
User signs tx → Backend relays tx → Blockchain
```

**Problem**: MetaMask's `eth_sendTransaction` **already submits** to blockchain. There's no "signed transaction" to relay.

**Correct Implementation**:
```javascript
// WRONG (from plan):
async _signWithMetaMask(txData) {
    const txHash = await provider.request({
        method: 'eth_sendTransaction',  // This SENDS, not just signs!
        params: [txParams]
    });
    return {signed_tx: txHash, tx_hash: txHash};  // No "signed_tx" exists
}

// CORRECT:
async _signWithMetaMask(txData) {
    // eth_sendTransaction signs AND broadcasts in one step
    const txHash = await provider.request({
        method: 'eth_sendTransaction',
        params: [txParams]
    });
    
    // No relay step needed - tx is already on blockchain
    return {tx_hash: txHash};
}
```

**Fix Required**: Remove Phase 4 "Relay" entirely. After signing, transaction is already submitted. Jump directly to Phase 5 (Monitor).

### C-2: Token Creation Flow is Architecturally Wrong
**Location**: Section 3.2  
**Issue**: Plan treats token creation as a user-signed transaction, but this breaks ownership model.

**Problem**:
```javascript
// User signs token deployment
await window.txManager.executeTransaction('create_token', formData, {...});
```

**Why This Breaks**:
- If USER deploys BondingCurvePool, USER becomes `owner()` (from OpenZeppelin Ownable)
- Platform loses admin control (pause, setGraduationOracle, etc.)
- Users pay deployment gas (~0.5-1 KAS per token) - expensive!

**Correct Architecture**:
```
USER submits form → BACKEND deploys via TokenFactory → BACKEND is owner
```

**Fixed Implementation**:
```javascript
// Frontend: Just submit form data, NO wallet signing
async function createToken(formData) {
    // 1. Upload image to IPFS first
    const ipfsHash = await uploadToIPFS(formData.image);
    formData.imageUrl = `ipfs://${ipfsHash}`;
    
    // 2. Backend deploys (using platform's oracle wallet)
    const response = await fetch('/api/token/create', {
        method: 'POST',
        body: JSON.stringify(formData)
    });
    
    // 3. Backend returns deployed contract address
    return response.json(); // {contract_address: '0x...', tx_hash: '0x...'}
}
```

```python
# Backend: Platform wallet deploys
@app.route('/api/token/create', methods=['POST'])
def api_create_token():
    data = request.get_json()
    
    # Platform's oracle wallet calls TokenFactory.createToken()
```

```javascript
            token_address: window.tokenContractAddress,
```

### H-1: Missing Slippage Parameters
**Location**: Section 3.3, trade execution  
**Issue**: Smart contract requires `minTokensOut` and `deadline` but plan doesn't pass them.

**Fix**: Add auto-slippage calculation:
```javascript
function calculateMinTokensOut() {
    const expectedTokens = parseFloat(document.getElementById('tokenAmount').value);
    const slippageBps = TokenDetail.autoSlippageBps || 50; // 0.5% default
    return expectedTokens * (10000 - slippageBps) / 10000;
}
```

### M-3: SSE Connection Not Cleaned Up
**Issue**: Plan stores SSE connections but doesn't show cleanup on page unload.

**Fix**: Add cleanup:
```javascript
class TransactionManager {
    constructor() {
        this.activeConnections = new Map();
        
        // Cleanup on page unload
        window.addEventListener('beforeunload', () => {
            this.closeAllConnections();
        });
    }
    
    closeAllConnections() {
        this.activeConnections.forEach(eventSource => eventSource.close());
        this.activeConnections.clear();
    }
}
```
